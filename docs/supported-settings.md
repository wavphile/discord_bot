# Supported server settings matrix

Status: design contract for the first inspection snapshot (M1) and later reviewed changes (M2). API references checked 30 October 2026.

The matrix defines the bot's initial configuration boundary. The current bot only implements `/health`; this document does not enable inspection or writes. Fields not listed here remain out of scope until they are reviewed and added explicitly.

## Planned first write set

These are future M2 operations, not current bot commands. Each change must use a reviewed plan with an exact target, current value, proposed value, requester, and expiry. Recheck current state and bot permissions immediately before writing. Send an audit-log reason with Discord write requests.

| Setting                          | Allowed target and values                                                                                                                                                                                     | API and required bot permission                                                                                                                                                                                                                                                                                                                          | Reversal                                                                                                                                            |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Channel topic                    | Ordinary text channels only; `null` or 0–1,024 characters. Forum and media channel topics are deferred.                                                                                                       | [`PATCH /channels/{channel.id}`](https://github.com/discord/discord-api-docs/blob/main/developers/resources/channel.mdx), requires `MANAGE_CHANNELS` for a guild channel.                                                                                                                                                                                | Restore the exact previous string or `null`.                                                                                                        |
| Slowmode (`rate_limit_per_user`) | Ordinary text channels only; integer seconds from 0 through 21,600. Zero disables slowmode. Bots and members with `BYPASS_SLOWMODE` are unaffected.                                                           | [`PATCH /channels/{channel.id}`](https://github.com/discord/discord-api-docs/blob/main/developers/resources/channel.mdx), requires `MANAGE_CHANNELS` for a guild channel.                                                                                                                                                                                | Restore the previous integer.                                                                                                                       |
| Selected channel permission bits | Custom, unmanaged role overwrites on ordinary text and voice channels. Text: `VIEW_CHANNEL`, `SEND_MESSAGES`, `READ_MESSAGE_HISTORY`. Voice: `VIEW_CHANNEL`, `CONNECT`, `SPEAK`. Do not change unlisted bits. | [`PUT` or `DELETE /channels/{channel.id}/permissions/{overwrite.id}`](https://github.com/discord/discord-api-docs/blob/main/developers/resources/channel.mdx), requires `MANAGE_ROLES`. Discord also limits the allowed/denied bits to permissions the bot has in the guild or parent channel, unless it has a `MANAGE_ROLES` overwrite in that channel. | Capture whether the overwrite existed and its complete previous `allow`/`deny` values. Restore those values, or delete the newly created overwrite. |

The first write set excludes `@everyone`, managed roles, member-specific overwrites, category overwrites, and permission bits that grant administration or moderation powers. Category overwrites can affect synced child channels, so category changes require a separate plan that explicitly lists every affected channel. Never replace a complete overwrite with only the bits displayed in a preview; preserve all existing bits.

Guild setting changes, base role permission edits, role assignment, channel creation/deletion, parent changes, channel ordering, forum tags, onboarding, automod, integrations, invites, and webhooks are not supported by the first write set. Add each only with its own permission, scope, and recovery review.

## Permission calculations

For a requested member and channel, calculate from the `@everyone` role and the member's role permission bitsets, then apply channel overwrites in Discord's documented order. The guild owner and `ADMINISTRATOR` are special cases; administrator permissions bypass channel overwrites. Preserve the source role and overwrite data so an explanation can show why a permission was granted or denied. Treat inaccessible or incomplete inputs as unknown, not as a denial.

See Discord's [permission hierarchy and overwrite order](https://github.com/discord/discord-api-docs/blob/main/developers/topics/permissions.mdx). Permission bitsets are 64-bit values and must not be converted to JavaScript `Number`.

## Visibility and completeness

The channel-list endpoint excludes threads. Discord's API documentation states that, starting 16 November 2026, it will omit channels the bot cannot view. The snapshot must represent the bot-visible scope and must not interpret an omitted or inaccessible channel as deleted. Require `VIEW_CHANNEL` for channels that the bot needs to inspect and report incomplete visibility when the source data cannot establish full coverage.

Permission explanations are requester-specific. Do not reuse an earlier member's calculated permissions for another requester. Channel visibility, role assignments, category synchronization, and administrator status can change between snapshots; re-fetch before any later write.
